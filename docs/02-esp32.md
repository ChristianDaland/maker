## Cheap Yellow Display (ESP32-2432S028R)

Kortene våre er «Cheap Yellow Display» (CYD): en vanlig ESP32-WROOM-32 med innebygd skjerm og mer. Stor samling eksempler og dokumentasjon: [witnessmenow/ESP32-Cheap-Yellow-Display](https://github.com/witnessmenow/ESP32-Cheap-Yellow-Display).

| Del | Detaljer |
|---|---|
| Skjerm | 2,8" 320×240, ILI9341 (noen varianter ST7789), HSPI: 13/12/14, CS 15, DC 2, baklys 21 |
| Berøring | XPT2046 (resistiv, trykk med negl eller penn), VSPI: 25/39/32, CS 33, IRQ 36 |
| RGB-LED | Rød 4, grønn 16, blå 17 – aktiv LAV |
| Lyssensor (LDR) | GPIO 34 (analog) |
| Høyttaler | GPIO 26 (kontakt P4) |
| SD-kort | VSPI: 18/19/23, CS 5 |
| Ledige pinner | 22, 27 (kontakt P3/CN1), 35 (bare inngang) |
| USB | CH340 → `/dev/ttyUSB0` |

Alt dette er samlet i biblioteket [`bibliotek/esp32/cyd`](../bibliotek/esp32/cyd/src/cyd.h), så prosjektene slipper å huske pinnenummer.

**Når kortene kommer: test ett kort først.** Det finnes flere varianter under samme navn (ILI9341 eller ST7789, én eller to USB-porter, inverterte farger). Last opp malen til `esp32-01`, sjekk farger, retning og berøring, og noter varianten her før de tre andre flashes:

| Kort | Skjerm | USB-porter | Farger OK | Berøring OK | Merknad |
|---|---|---|---|---|---|
| `esp32-01` | | | | | |

Kjente fallgruver:
- Få ledige pinner. Til flere sensorer: bruk I2C på 22/27, eller bytt ut SD-kortet.
- Er fargene feil eller bildet speilvendt, har kortet ST7789-skjerm: aktiver `-DCYD_ST7789` i `platformio.ini`.
- Berøringen er omtrentlig kalibrert. Treffer den skjevt, juster `x_min`/`x_max`/`y_min`/`y_max` i `cyd.h`.

## Nytt ESP32-prosjekt

```bash
~/maker/verktoy/nytt-prosjekt.sh esp32 "Navn på prosjektet"
```

Prosjektet får en ferdig `firmware/` fra [`prosjekter/esp32/_firmware-mal/`](../prosjekter/esp32/_firmware-mal/) som allerede:
- kobler til Wi-Fi og MQTT (med automatisk ny tilkobling og `online`/`offline`-status)
- viser status på skjermen og med RGB-LED (grønn = MQTT ok, rød = ikke tilkoblet, blå = starter)
- sender signalstyrke (`rssi`) og lysnivå (`lys`) hvert 10. sekund
- sender berøringer som JSON til `.../beroring`
- tar imot meldinger på `maker/<sted>/<enhet>/kommando/#`

Første gang:
1. `secrets.h` lages automatisk (gitignored). MQTT- og OTA-passord fylles inn fra `infrastruktur/.env`, og Wi-Fi fra `verktoy/sd-kort.env` hvis den finnes. MQTT-verten er `mqtt.local`.
2. Sett `ENHET` og `STED` i `firmware/include/config.h`.
3. `cd firmware && pio run -t upload && pio device monitor`

### MQTT-vert: mqtt.local

Kortene kobler til `mqtt.local`, ikke en IP-adresse. Maskinen som kjører broker, annonserer navnet (`infrastruktur/mqtt-navn.sh`). Når broker flyttes til `pi-sentral`, flytter navnet med – kortene trenger ikke flashes på nytt. ESP32 slår ikke opp `.local`-navn selv, så `maker_nett` gjør det med mDNS.

### Oppdatering over Wi-Fi (OTA)

Når `OTA_PASSORD` er satt i `secrets.h`, kan kortet oppdateres uten USB etter første opplasting. Hvert kort svarer på `<enhet>.local`:

```bash
set -a; . ~/maker/infrastruktur/.env; set +a
pio run -e cyd-ota -t upload --upload-port esp32-01.local
```

Malen har miljøene `cyd` (standard), `cyd-ota`, `wokwi` og `esp32dev` (vanlig ESP32 uten skjerm, f.eks. `pio run -e esp32dev`). Testbygget 2026-10-24: `cyd` bruker 59 % flash, `esp32dev` 49 % (partisjon `min_spiffs`, 1,9 MB til program, med plass til OTA).

## Simulering med Wokwi

[Wokwi](https://wokwi.com/) simulerer ESP32 (og Arduino og Pico) med skjerm, LED, sensorer og Wi-Fi. Vi bruker utvidelsen **Wokwi Simulator** i VS Code, som kjører firmwaren PlatformIO bygger. Det fungerer uten at et kort er koblet til.

Første gang: F1 → «Wokwi: Request a new License», og logg inn på wokwi.com. Lisensen er gratis for personlig bruk og åpen kildekode, men varer i 30 dager av gangen. Når den går ut, ber du om en ny lisens på samme måte. Se [wokwi.com/license](https://wokwi.com/license).

Alle ESP32-prosjekter har dette ferdig satt opp:

| Fil | Innhold |
|---|---|
| `firmware/diagram.json` | Koblingen i simulatoren: ESP32 + ILI9341-skjerm, RGB-LED og lyssensor på **de samme pinnene som CYD-kortet** |
| `firmware/wokwi.toml` | Peker på firmwaren fra `env:wokwi` |
| `env:wokwi` i `platformio.ini` | Som `cyd`, men bruker Wokwis Wi-Fi (`Wokwi-GUEST`) og MQTT-broker på PC-en (`host.wokwi.internal`) |

Slik kjører du:
1. Sørg for at infrastrukturen kjører (`docker compose ps` i `infrastruktur/`) og at MQTT-bruker og -passord står i `secrets.h`.
2. `cd firmware && pio run -e wokwi`
3. Åpne `diagram.json` i VS Code → F1 → «Wokwi: Start Simulator».
4. Følg med på meldingene i Node-RED (debug-panelet) eller med `mosquitto_sub`.

Begrensninger:
- **Berøring kan ikke simuleres.** Wokwi har ikke XPT2046-kontrolleren som CYD-kortene bruker.
- Baklyset og RST-pinnen på skjermen simuleres ikke (de spiller ingen rolle).
- Simulatoren er tregere enn ekte maskinvare, særlig Wi-Fi-tilkoblingen.
- At noe virker i simulatoren, er ingen garanti for at det virker på kortet (strøm, støy, tidskritiske ting).

## Koble til første gang

1. **Bruk en datakabel.** Mange USB-kabler er kun ladekabler (bare strømledere). Kortet lyser, men ingenting dukker opp i `dmesg`. Merk de kablene som fungerer.
2. Følg med på hva som skjer når du kobler til:
   ```bash
   sudo dmesg -w
   ```
   Forventet: en linje som `cp210x converter now attached to ttyUSB0` eller `ch341-uart converter now attached to ttyUSB0`. Kort med innebygd USB (S2/S3/C3) gir `ttyACM0`.
3. Får du «Permission denied» på porten: du er ikke i gruppen `dialout`. Forsvinner porten rett etter tilkobling: brltty stjeler den. Se [oppsett av PC-en](00-oppsett-pc.md#seriellporter-og-tilgang).
4. **BOOT-knappen:** Noen kort går ikke i flash-modus automatisk. Får du `Failed to connect to ESP32: Wrong boot mode detected` eller `Timed out waiting for packet header`, hold inne BOOT mens opplastingen starter (når `Connecting....` vises), og slipp når skrivingen begynner. Noen kort trenger i tillegg et trykk på EN/RST.

Rask sjekk med esptool:

```bash
esptool --port /dev/ttyUSB0 chip-id    # eldre versjoner: esptool.py --port /dev/ttyUSB0 chip_id
```

## To måter å programmere på

### PlatformIO (C++/Arduino-rammeverk)

Hovedvalget for prosjekter som skal vokse. Hvert prosjekt har en `platformio.ini` som beskriver kort, biblioteker og innstillinger, så prosjektet bygges likt hver gang. Legg PlatformIO-prosjektet i `firmware/` i prosjektmappen.

Eksempel på `platformio.ini`:

```ini
[env:esp32dev]
platform = espressif32
board = esp32dev
framework = arduino
monitor_speed = 115200
upload_port = /dev/ttyUSB0
lib_extra_dirs = ../../../../bibliotek/esp32   ; fra prosjekter/<plattform>/<prosjekt>/firmware/
```

Bygg, last opp og åpne seriell monitor fra PlatformIO-panelet i VS Code, eller fra terminalen med `pio run -t upload` og `pio device monitor`.

### MicroPython (Thonny / esptool)

Fint for rask utprøving og når du vil skrive Python.

1. MicroPython 1.29.0 for ESP32 ligger klar i [`verktoy/firmware/`](../verktoy/firmware/README.md) (gitignored). Nyere versjoner: micropython.org/download/ESP32_GENERIC.
2. Flash med esptool:
   ```bash
   esptool --port /dev/ttyUSB0 erase-flash
   esptool --port /dev/ttyUSB0 --baud 460800 write-flash 0x1000 ESP32_GENERIC-*.bin
   ```
   (Adressen er `0x1000` for vanlig ESP32, `0x0` for S3 og C3. Eldre esptool bruker `erase_flash` / `write_flash`.)
   Thonny kan også gjøre dette: Verktøy → Alternativer → Tolk → «Installer eller oppdater MicroPython».
3. I Thonny: velg tolk «MicroPython (ESP32)» og porten `/dev/ttyUSB0`. Last opp `.py`-filer; `main.py` kjøres ved oppstart.

Bare ett program kan ha seriellporten åpen om gangen. Lukk Thonny eller seriell monitor før du flasher.

## Felles kode

Gjenbrukbar kode legges i `bibliotek/esp32/`, med én undermappe per bibliotek. Se [bibliotek/esp32/README.md](../bibliotek/esp32/README.md) – foreløpig `maker_nett` (Wi-Fi/MQTT) og `cyd` (skjermkortet). Firmware-malen peker dit med `lib_extra_dirs`.

## Hemmeligheter (secrets-filer)

Wi-Fi-passord, MQTT-passord og API-nøkler legges i en egen fil som står i `.gitignore`:

- PlatformIO: `firmware/include/secrets.h`
- MicroPython: `secrets.py`

Lag alltid en eksempelfil med tomme verdier ved siden av, som sjekkes inn:

```c
// secrets.example.h – kopier til secrets.h og fyll inn
#pragma once
#define WIFI_SSID     ""
#define WIFI_PASSWORD ""
#define MQTT_HOST     "pi-sentral.local"
#define MQTT_USER     ""
#define MQTT_PASSWORD ""
```

Se [konvensjoner](konvensjoner.md).
